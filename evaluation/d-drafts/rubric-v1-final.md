一、每一份輸出，評分者要做的事（照順序）

1. 拿到的是匿名化、模式標籤已打亂的輸出。不要去猜它是 workflow、single 還是 dual。[手冊]
2. 先看該案例的「預期可支持主張」和「預期需拒絕主張」（案例檔裡有）。
3. 列出報告中的「關鍵可驗證主張」，每一個給一個編號（claim_id）。 [D初稿：關鍵主張的挑法，見第三節]
4. 每個主張標成 supported、unsupported、unknown 其中之一（定義見第二節）。
5. 檢查引用：每個引用能不能找到對應的快照、能不能讀。
6. 如果是有植入錯誤的案例，記錄「植入的錯誤有沒有被指出」「有沒有改對」。
7. 如果案例資料不足，記錄系統有沒有選 insufficient、有沒有說明缺口。
8. 寫完整份評分之後才可以看別人的分數。先獨立，再比對。[手冊]
9. 兩個人有差異，交給組長裁決，原始分數兩份都留著。[手冊]

------------------------------------------------------------
二、三種標註（沿用 rubric-v1）

supported：有來源，而且來源原文或工具輸出真的支持這個主張，且對得到同一版本的快照。只附一個網址不算。[手冊]
unsupported：有引用或有數字，但原文不支持、與來源衝突，或用錯口徑（例如幣別混用、單季當 TTM、季營收當全年營收）。[D初稿]
unknown：證據不足以判斷（來源讀不到、缺關鍵欄位、發布時間不明、證據在 cutoff 之後才出現）。不可當 supported，也不可直接當 unsupported。[D初稿]

名詞提醒：
unknown 是對「一個主張」的標註。
insufficient 是 Reviewer 對「整份報告」的決定。兩者不同。[手冊]

------------------------------------------------------------
三、哪些主張算「關鍵可驗證主張」[D初稿，需B確認]

算：含有數字、日期、比例、金額，或對事件的事實陳述，而且可以拿證據對照的句子。
不算：純意見、免責聲明、格式性文字、對未來的推測（推測要標成 inference，並看有沒有註明限制）。
如果一份報告沒有任何關鍵可驗證主張：證據支持率記為 NA，不是 0%，也不是 100%。[手冊]

------------------------------------------------------------
四、critical 問題（沿用 rubric-v1，仍待確認的部分標出）

1. 每一個 critical 都要指到具體的 claim_id。[手冊]
2. issues 每一項要有 claim_id、severity、reason、required_evidence 四欄。[手冊]
3. 不能因為文字通順或結論看起來正面就判通過。[手冊]
4. 公開報告不能留有未解決的 critical，否則只顯示「研究不足」或「未發布」。[手冊 E05]
5. 手冊對 Reviewer 的檢查清單九項（季度與累計混用、TTM 與單季混用、價格與 EPS/BVPS 不一致、CapEx 正負號、股數與淨負債不一致、WACC 不大於 g、財報期與可得時間搞混、2330 被當成 2454 同業平均、來源衝突未解決）是否全部算 critical，手冊沒有逐項寫明，待 B 確認。[D初稿]
6. 「資料品質風險」（高、中、低）是網站欄位，和這裡的 critical 不是同一件事。[手冊 F03]

------------------------------------------------------------
五、遇到「一個主張一半有支持、一半沒有」怎麼標 [D初稿，待B確認]

做法：拆成兩個主張分別標。例如「營收 1,000 億元，年增 20%」，數字對、年增率錯，就拆成兩條。
不能拆的情況：整句有一個不可分的數字，而那個數字有問題，整句標 unsupported。

------------------------------------------------------------
六、每個案例的評分紀錄欄位（給 B 和 D 各填一份）[D初稿]

case_id
run_id（匿名編號，不是模式名稱）
評分者（B 或 D）
claims：每個主張的 claim_id、標註（supported、unsupported、unknown）、理由一句話
引用總數、可解析引用數
植入錯誤：預期幾個、被指出幾個、修正幾個
拒答：是否選 insufficient、是否說明缺口
備註（模糊的地方）

整體統計用的分子、分母、NA 數，由 C 和 E 整理表格時計算；他們不判斷對錯。[手冊]

------------------------------------------------------------
七、評分者必須避免的事 [手冊]

1. 只看文字流暢度。
2. 把 mock 當成 live。
3. 用保留案的答案去調 prompt。
4. 刪除失敗的 run。
5. 缺值補數字，或把缺值當成 0。
6. 預設雙 Agent 一定比較好。
